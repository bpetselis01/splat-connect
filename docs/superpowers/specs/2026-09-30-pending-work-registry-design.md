# Pending work registry — design (sub-project 1 of 4)

Date: 2026-09-30 · Extends the sign-in pattern (`packages/mobile/lib/pending-features.ts`,
`PENDING(<id>)` markers, drift test) to every piece of unfinished work in the
codebase, measured against the Claude Design board
(`Splat Connect frontend overhaul/SPLAT Connect - {Mobile,Web}.dc.html`,
project `0cae93cb-…`).

## The four sub-projects

1. **This spec** — one registry for web, mobile and API; every gap the board
   shows is registered, marked in code, and (where it is a control) drawn and
   routed to "Not built yet".
2. Web parity — close the harness's styling findings.
3. Mobile parity — build a mobile measurement, close what it finds.
4. Build registered items — decision items first (Byron's calls), then build.

## Decisions (Byron, 2026-09-30)

| Question | Decision |
|---|---|
| Order | Registry first, then web parity, mobile parity, build |
| Registry home | `packages/types/src/pending.ts`, shared by web, mobile, API; checklist generated from it |
| Coverage | Every unfinished feature visible on the board, plus loose TODOs and sign-in setup |
| A board control the app lacks | Drawn in place; tapping opens "Not built yet". Data-only sections get a marker and no fake placeholder |

## How the inventory was taken

- Mobile: three read-only agents compared all 61 screens in
  `mobile-design-notes.md` with the app's routes, components and API calls,
  2026-09-30. Every board screen has a route; none is missing outright.
- Web: `scripts/parity/run.js` re-run 2026-09-30 — 92/118 clean, 55 findings;
  the `missing-section` findings that describe features (not sample-data
  volume, not styling) are registered. Styling findings are sub-project 2.
- Code: `git grep TODO`, `ComingSoon` pages, `state: 'soon'` nav rows,
  FEATURES.md "Known gaps", and the five sign-in items.
- The board's own "Not built yet" screens: mobile `ed_stl` (STL upload — since
  built in the app) and web `impact_map` (Deliveries map — registered).

## Design

### The item

```ts
export type PendingKind = 'setup' | 'content' | 'build' | 'decision'
export type PendingItem = {
  title: string                    // shown as the Not built yet heading
  blurb: string                    // one line shown under it
  kind: PendingKind
  platforms: ('web' | 'mobile' | 'api')[]
  board?: string                   // board screen(s) it comes from
  needs: string                    // what finishing it takes
  question?: string                // decision items: the call Byron makes
  shipped?: boolean
}
export const PENDING = { 'guide-step-tracking': { … }, … } satisfies Record<string, PendingItem>
export type PendingId = keyof typeof PENDING
```

- `packages/mobile/lib/pending-features.ts` is deleted; its five ids move here.
- Icons stay per platform: `packages/mobile/lib/pending-icons.ts` (Ionicons)
  and `packages/web/lib/pending-icons.ts` (Phosphor), each id → icon with a
  fallback.

### Surfacing

- **Mobile:** `<PendingButton id label …>` and `<PendingRow id label …>`
  (`components/ui/pending.tsx`) render like the real control and push
  `/not-built?feature=<id>`. `app/not-built.tsx` reads `PENDING`.
- **Web:** `app/not-built/[id]/page.tsx` in the board's `is_soon` shape;
  `components/pending-button.tsx` links there. `ComingSoon` takes its
  title/blurb from the registry; its `featureKey`s (`printing-parts`, `map`)
  become registry ids (`printing-parts`, `impact-map`), and the notify-signup
  allowlist follows.
- **Data-only gaps** (a stat, a field, a section fed by data that does not
  exist): a `PENDING(<id>)` comment in the component that will render it.
- **Content TODOs:** placeholder strings stay; their `TODO` becomes
  `PENDING(<id>)`. Legal items point at the board's `POLICY` draft copy
  (`SPLAT Connect - Web.dc.html` ~line 7667).
- Every id used appears at least once as a marker or a pending component.

### `docs/PENDING.md`

Generated by `node scripts/pending.mjs` from the registry: grouped by kind,
then board screen; decision items print their question (Byron's agenda for
sub-project 4); each row lists where its markers are. It supersedes
`docs/superpowers/plans/2026-09-30-sign-in-remaining-work.md` (deleted).

### Tests

`packages/api/tests/unit/pending-features.test.ts` imports the registry and
fails when: a marker or pending component names an unknown id; an open item
has neither; a shipped item leaves either behind; `docs/PENDING.md` differs
from the script's output. Unit tests for the pending components and the web
screen; one e2e per platform (a drawn control opens Not built yet with its
title).

### Also fixed now

`components/recycling/recycling-screen.tsx`: signed out, `load` returns before
clearing `loading`, so the skeleton spins forever.

## Out of scope

Building any item (sub-project 4); styling parity (2, 3); web `extra-section`
findings (the app does more than the board — not unfinished).
