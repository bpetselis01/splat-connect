# Integration Test Layer Implementation Plan (Phase 0 + Phase 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the local-Supabase test foundation and implement all 7 integration test suites plus the CI integration job, per `docs/superpowers/specs/2026-07-21-integration-e2e-test-layers-design.md` (Phases 0–1; the E2E Phase 2 gets its own plan after this one ships).

**Architecture:** Tests run through the real Hono app (`app.request()`) with real JWTs from a local Docker Supabase, exercising auth-middleware → route → RLS end-to-end. A small `src/app.ts` extraction separates app construction from `serve()`/dotenv so tests can import the app without binding a port or loading cloud credentials. Explicit per-suite cleanup (unique `@splat-test.local` users + tracked tutorial ids) instead of transactions, because PostgREST opens its own connections.

**Tech Stack:** Supabase CLI (Docker), Vitest, Hono `app.request()`, `@supabase/supabase-js`, `pg` (already devDeps).

## Global Constraints

- **NEVER point tests at the cloud project** `https://napjjvnriegcszcvkysj.supabase.co`. The integration setup file must throw unless `SUPABASE_URL` contains `localhost` or `127.0.0.1`.
- Local Supabase ports are the CLI defaults the existing helpers assume: API gateway `http://localhost:54321`, Postgres `postgresql://postgres:postgres@localhost:54322/postgres`.
- All test user emails end in `@splat-test.local` (the cleanup script keys on this suffix).
- `packages/api` is ESM — relative imports use the `.js` suffix (e.g. `../../src/app.js`).
- `tutorials` rows have **no FK to profiles** — deleting a test user does NOT delete their tutorials. Every suite that creates tutorials must delete them explicitly via the admin client in `afterAll`.
- The schema column is `approved` (boolean) on `profiles` — never `is_approved`.
- Node 22, pnpm 11 (matches CI).
- Commit after every green task; small commits with descriptive conventional messages.
- Docker must be running before any `supabase start` step.

### Task 2: Extract `src/app.ts` so tests can import the app

`src/index.ts` currently loads dotenv (cloud keys!) and calls `serve()` at module load — importing it from a test would bind port 3101 and load production credentials. Split it: `env.ts` (dotenv side-effects), `app.ts` (app construction), `index.ts` (env → app → serve). ESM evaluates side-effect imports in declaration order, so `import './env.js'` before `import app from './app.js'` preserves the current dotenv-before-app ordering.

```ts
import { createClient } from '@supabase/supabase-js'

const supabaseUrl = process.env.SUPABASE_URL ?? 'http://localhost:54321'
const serviceKey = process.env.SUPABASE_SERVICE_ROLE_KEY ?? ''

export interface TestUser {
  id: string
  email: string
  token: string
}

/** Service-role client for test setup, assertions, and cleanup. */
export function adminClient() {
  return createClient(supabaseUrl, serviceKey)
}

export async function createTestUser(
  role: 'contributor' | 'admin' = 'contributor',
  approved = true
): Promise<TestUser> {
  const admin = adminClient()
  const email = `test-${crypto.randomUUID()}@splat-test.local`
  const password = 'Test1234!'

  const { data: signUpData, error: signUpError } = await admin.auth.admin.createUser({
    email,
    password,
    email_confirm: true,
  })
  if (signUpError || !signUpData.user)
    throw new Error(`Failed to create test user: ${signUpError?.message}`)

  // WHY: the column is `approved` — a previous version wrote `is_approved`,
  // which doesn't exist, silently leaving every test user unapproved.
  await admin.from('profiles').upsert({ id: signUpData.user.id, role, approved })

  const anonClient = createClient(supabaseUrl, process.env.SUPABASE_ANON_KEY ?? '')
  const { data: sessionData, error: sessionError } = await anonClient.auth.signInWithPassword({
    email,
    password,
  })
  if (sessionError || !sessionData.session)
    throw new Error(`Failed to sign in test user: ${sessionError?.message}`)

  return { id: signUpData.user.id, email, token: sessionData.session.access_token }
}

export async function deleteTestUser(userId: string): Promise<void> {
  const admin = adminClient()
  await admin.auth.admin.deleteUser(userId)
}
```

```ts
    expect(res.status).toBe(200)
    const list = await res.json()
    expect(list.map((t: { id: string }) => t.id)).not.toContain(tutorialId)
  })
})
```

```ts
      .select('status')
      .eq('id', tutorialId)

    )
    expect(res.status).toBe(200)

  })
})
```

```ts
import { describe, it, expect, beforeAll, afterAll } from 'vitest'
import app from '../../../src/app.js'
import { createTestUser, deleteTestUser, adminClient, type TestUser } from '../../helpers/auth.js'

let user: TestUser

function uploadRequest(path: string, token: string, file: File) {
  const fd = new FormData()
  fd.append('file', file)
  fd.append('tutorialId', tutorialId)
  return app.request(path, {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}` },
    body: fd,
  })

  user = await createTestUser('contributor')
})

  if (photos?.length)
    await admin.storage.from('toy-photos').remove(photos.map((f) => `${tutorialId}/${f.name}`))

  await deleteTestUser(user.id)
})

    const { url } = await res.json()
    expect(url).toContain('/tutorial-pdfs/')
```
