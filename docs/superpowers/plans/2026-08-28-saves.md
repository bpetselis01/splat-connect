# Saves Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a signed-in person keep a tutorial, toy or design challenge and come back to it from a saved list under My SPLAT.

**Architecture:** One polymorphic `saves` table keyed `(profile_id, entity_type, entity_id)`. One Hono route group reads it in two queries — save rows, then entities through the user client, so RLS silently drops what the caller can no longer see. On the web, one `SaveButton` client component sits as a *sibling* of each card's whole-card anchor (a button inside an anchor is invalid HTML), opted in per call site. One shared slug map in `packages/types` decides which entity types are live; organisations and printable parts exist as enum values and `SOON` cards only.

**Tech Stack:** Postgres 15 + Supabase RLS, Hono, Next.js App Router (React server components + `'use client'` islands), Tailwind v4 with a `@layer components` pixel system, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-28-saves-design.md`

## Global Constraints

- **Migration number:** `044_saves.sql`. The last applied is `043_idea_graduated_notification`.
- **Enum values, exact:** `'tutorial'`, `'toy'`, `'challenge'`, `'organisation'`, `'printable_part'`. British spelling on `organisation`, matching the site's copy; note `public.organizations` the *table* is American, and that mismatch is deliberate — do not "fix" either.
- **URL slugs, exact:** `/dashboard/saved/tutorials`, `/dashboard/saved/toys`, `/dashboard/saved/challenges`. Plural in URLs, singular in the enum.
- **Live types are exactly three:** tutorial, toy, challenge. Organisations and printable parts get **no** save control, **no** list page, and **no** `SOURCE` entry.
- **Card default is save-off.** Omitting the `save` prop must leave each card byte-identical to today, including no wrapper element.
- **CSS:** the save button's hover rule goes in **its own selector**, never appended to the comma-grouped press-motion family list. Tailwind compiles a comma group into one `:is()`, and `:is()` takes the specificity of its most specific argument — that is the bug that once made every press on the site travel zero distance with nothing erroring.
- **Hover goes behind `@media (hover: hover)`** or a tapped card stays stuck lifted on a phone.
- **No admin RLS policy on `saves`.** A bookmark is not something an admin acts on.
- **Local Supabase is required** for Task 2 and Task 12: `supabase start`, then `packages/api/.env.test` points at `127.0.0.1:54321`.

- [ ] **Step 1: Write the migration**

```sql
-- 044_saves.sql
-- WHY: My SPLAT's cards promise "saved tutorials", "saved toys" and "saved
--      challenges", and nothing behind them existed. This is that storage.
--
-- One polymorphic table rather than five typed ones. entity_id therefore
-- carries NO foreign key, which is the deliberate trade: a hard delete leaves
-- an orphan row, and the read path never sees it because it joins to the
-- entity through the user client and RLS drops what the caller cannot read.
-- Five tables with real FKs would buy referential integrity for five RLS
-- policy pairs, five handlers and a union query — five copies of a table whose
-- only columns are who, what and when.

create type public.save_entity_type as enum
  ('tutorial', 'toy', 'challenge', 'organisation', 'printable_part');

create table public.saves (
  profile_id  uuid not null references public.profiles on delete cascade,
  entity_type public.save_entity_type not null,
  entity_id   uuid not null,
  created_at  timestamptz not null default now(),
  -- Composite PK does three jobs: uniqueness, an idempotent
  -- `on conflict do nothing`, and a direct index hit for "is this saved".
  -- No surrogate id — nothing ever references a save row.
  primary key (profile_id, entity_type, entity_id)
);

alter table public.saves enable row level security;

create policy "Read your own saves" on public.saves
  for select to authenticated using (profile_id = auth.uid());

create policy "Save as yourself" on public.saves
  for insert to authenticated with check (profile_id = auth.uid());

create policy "Unsave your own" on public.saves
  for delete to authenticated using (profile_id = auth.uid());

-- No admin policy, deliberately, and not an oversight. 041_toy_idea_reports
-- gave admins full access because a report is something an admin acts on; a
-- bookmark is not. With no policy defined for a role, every select by that
-- role returns zero rows regardless of what 004's default privileges grant.

-- The PK already serves "is this one saved". This serves the newest-first list.
create index saves_recent_idx on public.saves (profile_id, entity_type, created_at desc);
```

```ts
/**
 * What a save can point at.
 *
 * All five exist from day one so switching organisations and printable parts
 * on later is a code change rather than a migration. Only the three in
 * SAVE_SLUGS are live — see that constant.
 */
export type SaveEntityType =
  | 'tutorial'
  | 'toy'
  | 'challenge'
  | 'organisation'
  | 'printable_part'

/**
 * The live types, keyed by their URL segment.
 *
 * This is the single place that decides which types work. The API 404s on a
 * slug that is not a key here, and so does /dashboard/saved/[type] — one
 * missing key produces both behaviours, which is why it lives in @types rather
 * than being written twice.
 *
 * Plural in the URL, singular in the enum: a column value describing one row
 * should be singular, and a route listing many should not be.
 */
export const SAVE_SLUGS = {
  tutorials: 'tutorial',
  toys: 'toy',
  challenges: 'challenge',
} as const satisfies Record<string, SaveEntityType>

export type SaveSlug = keyof typeof SAVE_SLUGS

/** GET /api/saves/ids — every saved id the caller has, by slug. */
export type SavedIds = Record<SaveSlug, string[]>
```

```ts
// packages/api/src/routes/saves.ts
/**
 * Saves — the things a person kept to come back to.
 *
 * The list is two queries rather than a join, and that is forced: entity_id has
 * no foreign key (see 044_saves.sql), so PostgREST cannot embed it. Fetch the
 * save rows, then fetch those entities through the USER client — RLS drops what
 * the caller can no longer see, which is where "a donated toy silently leaves
 * your list" comes from. It is the absence of code, not a feature.
 */
import { Hono } from 'hono'
import { SAVE_SLUGS, type SaveSlug, type SavedIds } from '@splat-connect/types'
import { createUserClient } from '../supabase/user-client.js'
import type { AuthVariables } from '../middleware/auth.js'

const saves = new Hono<{ Variables: AuthVariables }>()

type Client = ReturnType<typeof createUserClient>
type Query = ReturnType<Client['from']>['select'] extends (...a: never[]) => infer R ? R : never

/**
 * The one object that decides which entity types are live.
 *
 * Selects are copied from routes/public.ts on purpose: a saved list returns the
 * same shape the public list does, so TutorialCard and ToyLibraryCard render it
 * unchanged. 'organisation' and 'printable_part' are in the enum and absent
 * here, so their routes 404 until someone adds a line.
 */
const SOURCE = {
  tutorials: {
    table: 'tutorials',
    select: '*, tutorial_orgs(status, organizations(id, name))',
    filter: (q: Query) => q.eq('status', 'approved'),
  },
  toys: {
    table: 'toys',
    select: '*, profiles(name), organizations(name)',
    filter: (q: Query) => q.eq('status', 'published').is('archived_at', null),
  },
  challenges: {
    table: 'toy_ideas',
    select: '*',
    filter: (q: Query) => q.eq('status', 'challenge'),
  },
} as const satisfies Record<SaveSlug, { table: string; select: string; filter: (q: Query) => Query }>

const isSlug = (s: string): s is SaveSlug => Object.hasOwn(SAVE_SLUGS, s)

saves.get('/ids', async (c) => {
  const { data, error } = await createUserClient(c.get('token'))
    .from('saves')
    .select('entity_type, entity_id')
    .eq('profile_id', c.get('userId'))

  if (error) return c.json({ error: error.message }, 500)

  const out = { tutorials: [], toys: [], challenges: [] } as SavedIds
  for (const slug of Object.keys(SAVE_SLUGS) as SaveSlug[]) {
    out[slug] = (data ?? [])
      .filter((r) => r.entity_type === SAVE_SLUGS[slug])
      .map((r) => r.entity_id)
  }
  return c.json(out)
})

saves.get('/:slug', async (c) => {
  const slug = c.req.param('slug')
  if (!isSlug(slug)) return c.json({ error: 'Not found' }, 404)

  const sb = createUserClient(c.get('token'))
  const { data: rows, error } = await sb
    .from('saves')
    .select('entity_id, created_at')
    .eq('profile_id', c.get('userId'))
    .eq('entity_type', SAVE_SLUGS[slug])
    .order('created_at', { ascending: false })

  if (error) return c.json({ error: error.message }, 500)
  if (!rows?.length) return c.json([])

  const source = SOURCE[slug]
  const { data: entities, error: entityError } = await source.filter(
    sb.from(source.table).select(source.select).in('id', rows.map((r) => r.entity_id)) as Query
  )
  if (entityError) return c.json({ error: entityError.message }, 500)

  // Re-sort into save order: the second query returns entity order, and RLS has
  // already removed anything the caller can no longer see.
  const byId = new Map((entities ?? []).map((e: { id: string }) => [e.id, e]))
  return c.json(rows.map((r) => byId.get(r.entity_id)).filter(Boolean))
})

saves.post('/', async (c) => {
  const body = (await c.req.json().catch(() => null)) as
    | { entity_type?: unknown; entity_id?: unknown }
    | null
  const type = body?.entity_type
  const id = body?.entity_id
  if (typeof type !== 'string' || typeof id !== 'string') {
    return c.json({ error: 'entity_type and entity_id are required' }, 400)
  }
  if (!Object.values(SAVE_SLUGS).includes(type as never)) {
    return c.json({ error: 'Unknown entity_type' }, 400)
  }

  // No existence or visibility check, deliberately: saving a uuid you cannot
  // see succeeds and then never appears in your list. It is not an oracle —
  // success and failure look identical to the caller either way — and the
  // alternative is an extra select on every save to prevent a free row.
  const { error } = await createUserClient(c.get('token'))
    .from('saves')
    .upsert(
      { profile_id: c.get('userId'), entity_type: type, entity_id: id },
      { onConflict: 'profile_id,entity_type,entity_id', ignoreDuplicates: true }
    )

  if (error) return c.json({ error: error.message }, 500)
  return c.body(null, 201)
})

saves.delete('/:slug/:id', async (c) => {
  const slug = c.req.param('slug')
  if (!isSlug(slug)) return c.json({ error: 'Not found' }, 404)

  // RLS scopes the delete to the caller's own rows, so someone else's identical
  // save is untouched and a miss is simply nothing deleted.
  const { error } = await createUserClient(c.get('token'))
    .from('saves')
    .delete()
    .eq('profile_id', c.get('userId'))
    .eq('entity_type', SAVE_SLUGS[slug])
    .eq('entity_id', c.req.param('id'))

  if (error) return c.json({ error: error.message }, 500)
  return c.body(null, 204)
})

export default saves
```

```tsx
// packages/web/components/save-button.tsx
'use client'

/**
 * Keep a thing to come back to.
 *
 * Used two ways: as an island over a card's photo (the card is one whole-card
 * <Link>, and a <button> inside an <a> is invalid HTML with an ambiguous click
 * target — so this renders as a SIBLING of the anchor, never a child), and as
 * an ordinary control in a detail page's header row.
 *
 * Signed-out visitors see it. Clicking sends them to /signup rather than
 * /login: the auth screens carry a segmented switch, so someone who already has
 * an account crosses over in one click, while the reverse assumes an account
 * that most of /library's traffic does not have.
 */
import { useState, useTransition } from 'react'
import { useRouter, usePathname } from 'next/navigation'
import type { SaveSlug } from '@splat-connect/types'
import { browserApiClient } from '@/lib/browser-api-client'
import { useToast } from '@/components/toast'
import { SAVE_SLUGS } from '@splat-connect/types'

export type SaveProps = {
  slug: SaveSlug
  id: string
  saved: boolean
  signedIn: boolean
}

export function SaveButton({
  slug,
  id,
  saved,
  signedIn,
  className = '',
}: SaveProps & { className?: string }) {
  const [on, setOn] = useState(saved)
  const [, startTransition] = useTransition()
  const router = useRouter()
  const pathname = usePathname()
  const showToast = useToast()

  async function toggle() {
    if (!signedIn) {
      router.push(`/signup?next=${encodeURIComponent(pathname)}&reason=save`)
      return
    }

    const next = !on
    setOn(next) // optimistic: the click is the feedback, not the round trip
    try {
      if (next) {
        await browserApiClient.post('/api/saves', {
          entity_type: SAVE_SLUGS[slug],
          entity_id: id,
        })
      } else {
        await browserApiClient.delete(`/api/saves/${slug}/${id}`)
      }
      startTransition(() => router.refresh())
    } catch {
      setOn(!next)
      showToast(next ? 'Could not save that. Try again.' : 'Could not remove that. Try again.', 'error')
    }
  }

  return (
    <button
      type="button"
      onClick={toggle}
      aria-pressed={on}
      aria-label={on ? 'Saved' : 'Save'}
      title={on ? 'Saved' : 'Save'}
      className={`save-btn ${on ? 'is-saved' : ''} ${className}`.trim()}
    >
      <svg viewBox="0 0 12 15" aria-hidden="true" className="h-[15px] w-[12px]">
        <path
          d="M1 1h10v13l-5-4-5 4z"
          fill={on ? 'currentColor' : 'none'}
          stroke="currentColor"
          strokeWidth="2"
          strokeLinejoin="round"
        />
      </svg>
    </button>
  )
}
```

```ts
import { cache } from 'react'
import type { SavedIds } from '@splat-connect/types'
import { apiClient } from '@/lib/api-client'
import { getCapabilities } from '@/lib/capabilities'

const EMPTY: SavedIds = { tutorials: [], toys: [], challenges: [] }

export const getSavedIds = cache(async (): Promise<SavedIds | null> => {

  // should cost an unfilled bookmark, not a browse grid.
  return apiClient.get<SavedIds>('/api/saves/ids').catch(() => EMPTY)
})
```

```tsx
import { SAVE_SLUGS, type SaveSlug } from '@splat-connect/types'
import { getCapabilities } from '@/lib/capabilities'
import { apiClient } from '@/lib/api-client'
import { TutorialCard } from '@/components/tutorial-card'
import { ToyLibraryCard } from '@/components/toy-library-card'
import { ChallengeCard } from '@/components/challenge-card'

const VIEW = {
  tutorials: { title: 'Saved tutorials', browse: '/library', browseLabel: 'Browse the library' },
  toys: { title: 'Saved toys', browse: '/toy-library', browseLabel: 'Browse the toy library' },
  challenges: {
    title: 'Saved challenges',
    browse: '/get-involved/design-challenges',
    browseLabel: 'Browse design challenges',
  },
} as const satisfies Record<SaveSlug, { title: string; browse: string; browseLabel: string }>

export default async function SavedList({ params }: { params: Promise<{ type: string }> }) {
  const { type } = await params
  if (!Object.hasOwn(SAVE_SLUGS, type)) notFound()
  const slug = type as SaveSlug

  const caps = await getCapabilities()
  if (!caps) redirect('/login')

  const items = await apiClient.get<{ id: string }[]>(`/api/saves/${slug}`).catch(() => [])
  const view = VIEW[slug]

  return (
    <div>
      <h1 className="title-hub">{view.title}</h1>
      {items.length === 0 ? (
        <p className="mt-4 text-base text-muted">
          Nothing saved yet.{' '}
          <Link href={view.browse} className="font-bold text-brand-deep underline">
            {view.browseLabel}
          </Link>
          .
        </p>
      ) : (
        <div className="mt-8 grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3">
          {items.map((item) => {
            const save = { slug, id: item.id, saved: true, signedIn: true } as const
            if (slug === 'tutorials') return <TutorialCard key={item.id} tutorial={item as never} save={save} />
            if (slug === 'toys') return <ToyLibraryCard key={item.id} toy={item as never} save={save} />
            return <ChallengeCard key={item.id} idea={item as never} save={save} />
          })}
        </div>
      )}
    </div>
  )
}
```

### One thing the spec got wrong, found only on the built page

**The saved hub was specified at 4-up.** "Ready now" holds exactly three cards,
so at 4-up it left a dead column on any screen wide enough to show one. Changed
to 3-up — `HubGrid`'s default, and what `/learn` uses for the same shape. Fixed
in `48e96ce4`; the screenshot above is the corrected version.

### Two departures from the plan, both deliberate

- **Organisations and printable parts got `ComingSoon` routes**, not hub cards
  pointing back at the hub. The plan had both placeholders sharing
  `/dashboard/saved` as an href, which collides on `HubGrid`'s React key and
  reads as broken when clicked. `/dashboard/print-requests` already establishes
  the pattern. Static segments beside `[type]`, so they win the route match.
- **`.save-btn` joins the press-motion family `:is()` group.** The plan said
  keep it out. Re-reading the trap, it applies to *high-specificity* selectors
  only; a plain class is the group's designed extension point. The rule that
  genuinely must stay separate is `.save-host:hover .save-btn`, and that one is,
  mutation-checked.
