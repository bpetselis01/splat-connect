# Journey coverage (web + mobile) Requirements

**Version:** 1.0
**Status:** Draft
**Date:** 2026-10-20

## Problem Frame

Mobile has a journey map (`packages/mobile/tests/journeys.json`, 253 rows) and a CI check (`scripts/journeys/check.mjs`) that fails when a row's required layer has no tagged test. It reports 0 gaps. That number is honest about the map it knows and misleading about the app: the map froze on the day it was transcribed (2026-10-07), so the 17 screens shipped since (event detail/register/print and the organiser's registrations list, the acting-org switcher, six admin queues, My reports, thank-you notes, guide collaborators, report-a-person, the org-edit sections) cannot show as gaps; 2 rows are stale and ~6 partial; and the 13 device-layer cells point at Maestro flows that have never run in CI.

Web has no map at all. The scouts derived 350 journey rows across 134 pages. 137 Playwright tests exist (about 40% assert only that something renders), 14 routes have no test at any layer, 36 more are covered only through a child component, no web test asserts that any of the 38 notification types reaches its recipient, server actions have no unit tests, and `app/` is excluded from coverage. The API ratchet (`route-coverage.test.ts`) matches path but not method, so 4 untested routes hide behind it in addition to the 9 it lists.

The problem is not a shortage of tests. It is that nothing makes the inventory stay complete, and nothing checks that a tag sits on a test that proves the journey's outcome. Fix those two and the gap-closing work stays closed.

| R5 | The map's layers become `web-unit`, `web-e2e`, `mobile-unit`, `mobile-e2e`, `api`, `device`. `api` is shared. | Must Have | `scripts/journeys/lib.mjs` LAYERS. |

| R9 | Every gap the audit found is closed: the 14 web routes with no test, the 36 covered only through a child component, the ~55 render-only web e2e tests (upgraded to assert an outcome or left untagged), the 2 WRONG mobile unit tags (G09, G10), the ~9 loose tags, and all rows added under R2 and R3. | Must Have | Gap list is generated by the checker after R1–R8 land, not hand-maintained. |
| R10 | The API ratchet matches method and path. The 9 listed and 4 hidden untested routes get integration tests and the `UNTESTED` set empties. | Must Have | Hidden: `POST`/`DELETE /api/tutorials/:id/stl-files`, `GET /api/admin/organization-requests`, `GET /api/contributors/me/thanks`. |
| R11 | Each of the 38 notification types has an api test that triggers it through its real route and asserts the row (type, recipient, link), and an e2e on the client that owns the trigger asserting the recipient sees it. | R12 | Android Maestro becomes a required CI check on pull requests that match the existing `mobile` path filter (`packages/mobile`, `packages/types`, `packages/api`, `supabase`): Release build against local Supabase, the 13 flows. ## Success Criteria

- `pnpm test:journeys` passes with 0 gaps against a map that names every `page.tsx` and every mobile route file; adding a route without a row, or a row without a tagged test case, fails CI.
- A re-run of the audit's 50-row sample (and a fresh 50-row sample of web rows) finds ≥ 48/50 OUTCOME per required layer.
- `route-coverage.test.ts` has an empty `UNTESTED` set and matches on method + path.
- The Android Maestro job is green on `development` and required.
- Every notification type has a passing api test that triggers it through its real route.

## Scope Boundaries

**In scope:**
- The journey map, checker, tripwire, layer policy and doc for both platforms.
- New and upgraded tests at every layer, on both clients and the API, to reach 0 gaps under R6.
- Android Maestro in CI.
- R15 (the XSS) and the bug register (R16).

**Out of scope:**
- Fixing the product bugs in Outstanding Questions (each is a product decision).
- iOS Maestro in CI (no macOS runner budget decided).
- Visual parity against the boards (`scripts/parity` stays as is).
- Coverage-percentage thresholds; the map is the measure, not line coverage.
- New features the inventory shows are missing on one platform (that is the parity plan's job).

## Key Decisions

| Decision | Chosen | Rationale | Alternatives Considered |
|----------|--------|-----------|------------------------|
| Mechanism | Keep `journeys.json` + tagged tests + `check.mjs`; re-derive both inventories | The mechanism works where it is fed (46/50 unit, 45/49 e2e, 39/45 api OUTCOME in the sample); the inventory is what rotted | Fresh mechanism; web-only extension trusting the mobile map |
| Bar for "covered" | Outcome at every required layer | A render test tagged with a journey reads as coverage and isn't; ~40% of web e2e is render-only | Outcome at e2e + api only; any tag counts |
| Device layer | Promote Android Maestro to a required PR check on the `mobile` path filter, no nightly | Only layer that runs on Hermes, which has caught bugs no other runtime shows; API and schema changes are what break phone journeys | Nightly only; narrower filter (mobile + types); waive by hand; drop the layer |
| Tag parsing | TypeScript AST walk, not a regex | 84 mobile unit files, 11 web and 15 api use `.each`; a regex also counts skipped and commented-out tests | Regex per runner; `vitest list --json` (runs the runner) |
| Seed helpers | One Playwright-free module both e2e suites and the device provisioner import | Web and mobile `helpers.ts` already duplicate ~100 lines each and the plan would add five more copies | Keep per-package helpers |
| Tag granularity | Per test case | File-level tags let one file vouch for 13 journeys | Keep file-level with a fan-out cap |
| Bugs found | Register, don't fix (except the XSS) | Each is a product decision and would double the plan | Fix in this plan |
